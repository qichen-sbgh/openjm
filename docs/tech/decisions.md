## D1 加密方案：全量流式 + 尾部 MAC

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 仅头部/局部混淆 | 否 | 内嵌图片与文本流会被深度扫描，等于没加密 |
| 加密 ZIP 改后缀 | 否 | 保留 `PK` 头与 ZIP 目录特征，且 PDF 二次压缩耗电无收益 |
| 全量滚动 XOR | 否 | 需自研完整性校验，密钥流复用风险高 |
| **全量 AES-128-CTR + 尾部 HMAC-SHA256** | **选** | 全量高熵密文；硬件加速；天然支持任意偏移 Seek（为 FR-19 留路） |

代价：比“改后缀”多写一层协议；但换来抗扫描 + 完整性 + 未来 Seek，一次付清。

## D2 完整性：Encrypt-then-MAC，错误只分三类

一次 HMAC 比对同时挡掉**截断、损坏、篡改、口令错**四种情况。代价是这四种在错误类型上不可区分——`JMAuthError` 一句“文件不完整或已损坏，请在 QQ 重新下载”兜住。

这是有意的：要靠 HMAC 之外的信息去猜“到底是哪种”，反而会引入可被利用的旁路判断。

## D3 密钥：内置根密钥 + `key_id` 版本化，口令作为可选层

- 日常分发零输入摩擦（P0 体验），高敏文档才加口令；
- `key_id` 1 字节换来“换密钥不用改协议、老文件不立即失效”；
- 口令模式 `key_id` 写 0，避免“口令 + 根密钥”两套语义纠缠。

被否掉的：只做口令模式（每次输密码，群里没人用）、只做单密钥（轮换即全体失效）。

## D4 防风控三件套：随机 nonce + 脱敏命名 + 随机填充

| 手段 | 挡掉什么 |
| --- | --- |
| 每份文件新 16B nonce | 同一 PDF 的哈希指纹（秒传/黑名单比对） |
| 输出名 `doc_日期_随机.jm` | 明文文件名敏感词过滤 |
| 0–4096 随机填充 | 固定字节体积指纹 |

代价：每份文件体积略增（≤4KB），几乎无感。

## D5 发送端形态：Python SDK，只依赖 `cryptography`

被否掉的：Go/Rust 单文件二进制（打包与跨平台成本高）、Node（群里发文件的多是 Python 脚本）。

代码在 [`openjm-sdk`](https://github.com/qichen-sbgh/openjm-sdk)，设计见 [`sdk.md`](sdk.md)。

## D6 移动端：KMP + Compose Multiplatform，PDF 走平台原生

- 共享：协议解析、密钥派生、本地数据库、书架与阅读 UI；
- 不共享：PDF 渲染。Android 用 PDFium 社区封装（避开厂商 ROM 字体缺失与 `PdfRenderer` 缩放模糊），iOS 用 `PDFKit`（零额外体积且锐利）。

被否掉的：纯原生双端（协议实现写两遍，必然跑偏）、WebView + pdf.js（内存与大文件都不行）。

## D7 存储：校验通过即解密进私有沙盒，不留 `.jm`

- 省一半手机空间；
- 二次打开秒开（不用重复解密）；
- 天然满足“不导出明文”（沙盒对文件管理器和相册不可见）。

代价：无法做“原文再分享”，这是产品上明确接受的（见需求 §3 非目标）。

## D8 持久化与基线：Room KMP，Android 8.0+ / iOS 15.0+

对齐 CMP 官方稳定基线，避开老旧系统的加密与分区存储坑。代价是放弃一部分老设备，群内分发场景可接受。

## D9 分发：首版群内直发，不上商店

跳过商店审核与“空壳应用”判定风险，最快跑通闭环。代价：没有强制更新，旧版本会长期存在——这也是为什么协议必须有版本位、密钥必须能轮换。

## D10 平台顺序：Android 先跑通，iOS 冻结

**决定**：后续迭代资源全部投 Android，直到“导入 → 沙盒 → 书架 → 阅读 → 进度”闭环稳定；iOS 代码保留在仓库，但**不编译、不验证、不作为发布门槛**。

**理由**：KMP 共享层能覆盖协议与大部分 UI，但两端原生部分（唤起、沙盒、渲染、权限）几乎没有交集，并行推进等于两份真机调试，而不是“写一份跑两端”。当前工具链也没有 Xcode，强行对齐只会往仓库里堆未经验证的代码。

**代价**：iOS 侧 `CommonCrypto` 实现会长期停在“写完没编译”的状态，回头对齐时可能要重写部分 cinterop 代码；QQ 在 iOS 上的唤起行为届时也要重新验证一遍。

**重新考虑的条件**：Android 主路径连续两个迭代跑通，且 11 个向量在 Android 侧全过。

**已排除的方案**：两端并行（真机成本翻倍、故障点翻倍）；先做 iOS（当前工具链更缺，且 QQ 群文件的痛点主要在安卓侧）。
