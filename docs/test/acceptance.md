## 2. 通过标准

一个版本可以发，必须同时满足：

1. 追溯矩阵里所有 **P0 需求**状态为 ✅ 或 🟡（🟡 必须写明缺什么、为什么可以放行）；
2. L0 / L1 全绿；
3. 当前支持平台的 L2 向量 100% 通过；
4. 无 S1 / S2 未关闭；
5. 已知问题清单有人签字（自己签也算）。

平台口径：当前发版门槛只覆盖 Android，iOS 相关项在 M4 之前不参与判定（见 [`iteration.md`](../process/iteration.md) §3.1）。


## 3. 真机清单

> 机型选择原则：选**最容易出问题**的四家 ROM，而不是选最新的。清单一旦定下就固定，每次回归用同一批，便于横向对比。

### 3.1 Android

| 项 | 步骤 | 期望 |
| --- | --- | --- |
| 唤起（标准） | QQ 群文件点开 `.jm` | 直接进 App 并开始导入 |
| 唤起（无后缀） | QQ 转发到“我的电脑”再点开 | 同样能进（靠魔数，不靠后缀） |
| 唤起（被改名） | 手工改名成 `.jm.1` 后点开 | 同样能进 |
| SEND 路径 | QQ“用其他应用打开” → openjm | 进 App |
| ROM 拦截兜底 | 系统设置里关掉 openjm 的文件关联后再点开 | 点不开，但首页“导入 .jm”可用 |
| 非 .jm 文件 | 选一个普通 PDF 点开 | 明确提示“不是 .jm”，不崩 |
| 沙盒 | 导入完成后用文件管理器翻外部存储 | 找不到明文 PDF，也找不到 `.jm` |
| 截断 | 传入 `v90-truncated.jm` | 提示重新下载，书架无残留条目 |

### 3.3 阅读与进度

| 项 | 步骤 | 期望 |
| --- | --- | --- |
| 首开 | 打开一本书 | 有封面、有进度、能翻页 |
| 进度恢复 | 翻到第 10 页，杀进程，重进 | 回到第 10 页同位置 |
| 横竖屏 | 阅读中旋转 | 不跑偏（`scrollRatio` 生效） |
| 去重 | 同一文件再导入一次 | 书架仍一条，进度不丢 |
| 排序 | 读一本旧书 | 该书上浮到最近阅读 |

### 3.4 口令

| 项 | 步骤 | 期望 |
| --- | --- | --- |
| 首次 | 导入 `v03-password.jm`，输入正确口令 | 导入成功 |
| 错误口令 | 输入错误口令 | 提示重新下载或重试口令，不产生条目 |
| 免密 | 已导入后再次打开 | 不再弹口令 |
| 缺口令 | 点开后直接返回 | 不产生条目、不留临时文件 |

## 4. 验收记录落在哪

**不落成仓库文件。** 每轮收口的验收结果（跑了哪些、过了几项、已知问题）写在 PR 描述里，PR 合上就进 git 历史。

本文件只维护**当前有效**的追溯矩阵与真机清单：状态变了就改格子，不要追加“第二轮”“第三轮”的表格。要看某一轮验了什么，去 `git log -p docs/test/acceptance.md` 或对应的 PR。
