## 1. 目标

一句话：**三端对同一份字节流给出同一份结论**。所有测试都是为这句话服务的，其余都是次要的。

这也决定了测试的重心在协议层（L2），而不是 UI 层——UI 出问题用户能忍，字节对不上就是文件打不开。

## 2. 分层

| 层 | 内容 | 跑在哪 | 触发频率 |
| --- | --- | --- | --- |
| L0 静态 | 向量清单结构校验（长度恒等式、明文 sha256、头部字段）、CI 配置 | GitHub Actions | 每次 push |
| L1 单元 | SDK 30 例（往返/随机性/口令/截断/篡改/分块/原子落盘/CLI）；移动端 20 例（向量回放 3 + 沙盒落盘 6 + 书架/进度 6 + 持久化 5） | 本地 + CI | 每次 push |
| L2 协议向量 | 11 个冻结向量在三端回放（5 valid + 6 invalid） | 本地 + CI（Python 全量；Android 在本地回放，CI 无向量仓检出时 skip） | 每次 push / 协议变更时三端必跑 |
| L3 端到端 | QQ → 唤起 → 导入 → 书架 → 阅读 → 杀进程恢复 | 真机 | 每个迭代收口 |
| L4 兼容矩阵 | 4 家国产 ROM + iOS 真机组合 | 真机 | 每个发版 |
| 性能 | 50MB 解密耗时、内存峰值 | 真机 | 每个发版 |

## 4. 自动化现状

| 范围 | 用例数 | 状态 |
| --- | --- | --- |
| 总仓向量结构校验 | 11 向量 | ✅ CI 绿 |
| SDK 单测 | 30 | ✅ 本地 + CI 绿 |
| SDK 跨端向量回放 | 12 | ✅ 绿 |
| 移动端 androidHostTest | 20（3 向量回放 + 6 沙盒落盘 + 6 书架/进度 + 5 持久化） | ✅ 本地全过；CI 里向量相关的 9 例 skip，其余 11 例照跑 |
| 移动端模拟器 E2E | 6 步（空书架 → VIEW 导入 → 阅读 → 返回写进度 → 杀进程还原 → 口令三条路径） | ✅ 本地一条命令：`openjm-mobile/tools/emulator-e2e.ps1`，未进 CI |
| 移动端真机 E2E | 0 | ⬜ 手工 |

> 移动端已能编译并回放向量（M1 完成），L2 在 Android 侧不再是缺口。
> L3 的**数据链路**（导入、沙盒、去重、进度回填）已在模拟器上跑通；剩下的缺口是**真机 ROM 差异**
> （QQ 唤起、SAF 兜底、沙盒对文件管理器不可见）与 **L4 兼容矩阵**，只能靠真机清单。

## 5. 执行策略

- **每次 push**：L0 + L1 自动跑，红了不许合并（见 [`iteration.md`](../process/iteration.md) §4）。
- **每次改协议或向量**：L2 必须在三端各跑一遍，结果贴到 PR 描述里。
- **每个迭代收口**：先跑 `openjm-mobile/tools/emulator-e2e.ps1 -Fresh`（模拟器端到端，一条命令），再按真机清单验 ROM 相关项（唤起、SAF、沙盒可见性）。
- **每个发版**：L4 兼容矩阵 + 性能采样，结果写进 PR 描述（不落成仓库文件）。

## 6. 缺陷分级

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| S1 阻断 | 打不开 / 崩溃 / 明文丢失 / 书架数据被覆盖 | 立即修，阻塞发版 |
| S2 严重 | 进度丢失、重复导入覆盖、错误提示误导 | 当轮修，阻塞发版 |
| S3 一般 | UI 错位、文案不准、排序不符预期 | 排进下一迭代 |
| S4 轻微 | 视觉细节、日志噪音 | 有空再说 |

## 7. 退出标准（一个迭代算完成的条件）

1. L0 / L1 全绿；
2. L2 向量在当前支持的平台上 100% 通过，未支持平台明确列出并注明原因；
3. 无 S1 / S2 未关闭；
4. 新增行为都有对应测试或明确的“手工验证记录”；
5. 文档三件套已同步（需求 / 技术 / 测试），见 [`doc-rules.md`](../process/doc-rules.md)。

## 8. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 没有真机环境 | L3/L4 全靠手工，容易漏 | 先锁定 4 个代表机型，清单写死，每次同一批 |
| 移动端迟迟不能编译 | 协议核心无法被验证 | 已解除（M1）：`assembleDebug` 与 androidHostTest 都进了 CI 与本机门禁 |
| iOS cinterop 类型不确定 | 首次编译会返工 | 已把 CTR 实现绕开 `kCCModeOptionCTR_BE`，减少不确定性 |
| QQ 客户端版本行为变化 | 唤起失效 | 魔数判定 + SAF 兜底；每次 QQ 大版本更新回归一次 |
| 口令错误与文件损坏不可区分 | 用户提示可能误导 | 已在需求上接受，文案统一为“重新下载或重试口令” |
